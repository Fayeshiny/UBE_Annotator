# 长视频子任务

默认按 300 秒划分核心标注范围，例如 30 分钟视频得到 6 个子任务，最后不足 5 分钟的部分单独成段。每段核心范围首尾最多附加 10 秒上下文，可回看、播放，不能在上下文上标注。相邻核心范围使用半开区间，帧不重复分配；分段依据实际帧时间戳，不依赖固定 FPS。

## 使用

1. 保存现有标注并强制刷新 8001 工作台。长视频顶部出现“视频子任务”选择器。短于一段的视频保留整段工作流。
2. 等待病例列表显示子视频全部就绪。导入原视频后，服务器自动排队生成全部子视频；已有视频在服务启动时自动补齐。准备中显示已完成段数，标注入口暂不开放；直接访问任务链接也会显示整体准备状态并自动刷新。失败时管理员或复核者可重试失败片段。
3. 开始标注后选择任意子任务，直接读取已保存的独立 MP4，不触发切分。浏览器缓存当前段，完成后显示“本段视频已缓存”。
4. 标注完成后点击“标记本段完成”。这是进度记录，最终提交仍执行现有全病例必填项检查。相关内容再次修改会使受影响的已完成标记失效。跨段事件补齐结束、恢复或修改共同结构信息后，可能需要回看并重新确认之前受影响的段。
5. 切段会先保存，正在加载或传播的 SAM 会话完成后才能切段。浏览器仅保留当前子视频临时缓存；服务器已生成的子视频供所有被授权标注者复用。
6. 所有段完成后，按原来的父任务流程统一提交、复核和导出。

## 时间、事件与结构

- 数据库始终保存同一父任务的完整标注，不复制、重编号或平移已有标注；采样网格也保持全局位置。子任务继承父任务的标注者和权限。
- 播放使用子视频的真实局部帧时间戳，显示和保存时映射回全局帧号。视频生成后先核对帧数与全部 PTS，相差超过 1 ms 则拒绝发布。
- 情境、可评价状态继承前段状态；编辑只应用到当前核心范围。上下文以灰色遮罩显示。其他段检查项或里程碑的定位会提示先选择相应子任务。
- 跨段事件保持原事件 ID。结束或恢复可以在后续子任务补标；恢复点未记录的事件持续显示在后续子任务。
- SAM 的抽帧、提示、掩膜和导出继续使用完整播放源与全局帧号。工作台新建 SAM 会话时只读取当前子任务内选定的片段；原有跨段会话需在当前段重新建立后再操作。
- 原有结构目标和掩膜不会拆分。选择上一段已有目标后，可点击“延续 Oxxx 到本段末”保留目标 ID，并在当前段重新提示、传播；不会自动将上一段模型状态传播过边界。
- 展示用子视频以原分辨率、原帧率、H.264 CRF18 重编码，每 15 帧关键帧，移除音轨与元数据。原播放源不替换，精确远程 JPEG 和 SAM 抽帧仍来自原播放源。本地缓存播放的是子视频。
- 导出仍是一份完整病例数据，事件、SRT、掩膜及各轨道使用全局坐标，不分别输出重叠子任务。

## 配置与接口

新病例首次生成分段计划时读取环境变量，随后计划持久化在 SQLite 中，重启或调整环境变量不会悄悄改变已有任务：

```bash
export SSI_SEGMENT_SECONDS=300
export SSI_SEGMENT_CONTEXT_SECONDS=10
```

管理员在工作台选择“调整视频分段”可修改该病例段长（30–1800 秒，界面上下文固定 10 秒）。接口 `PUT /api/cases/{case_id}/segment-plan` 接受 `{seconds, context_seconds}`，上下文可配置 0–30 秒。调整保留全部标注、清除子任务完成状态；存在已提交/通过任务或病例已锁定时禁止调整。

- `GET /api/assignments/{aid}`：`segments` 给出核心和上下文的全局帧范围、版本、完成状态。
- `GET /api/cases/{case_id}/segments/{index}`：只读取已准备的子视频元信息和帧映射，不排队或启动 FFmpeg。旧的 `POST .../{index}/prepare` 保留为只读兼容接口。
- `POST /api/cases/{case_id}/segments/prepare`：管理员或复核者排队准备该病例全部子视频；保留完整文件，重试失败或缺失片段。
- 病例和任务响应中的 `segment_preparation`：`status`（waiting/queued/processing/ready/error）、`total`、`ready`、`failed`、`error`。与标注完成进度分开。
- `GET/HEAD /api/cases/{case_id}/segments/{index}/video?revision=...`：鉴权、版本检查及 Range 传输。
- `GET /api/cases/{case_id}/segments/{index}/video-index`：子文件局部帧到字节范围，沿用当前位置优先下载。
- `POST /api/assignments/{aid}/segments/{index}/completion`：`{completed,version,revision}`，校验父任务可编辑性及版本。

文件位于 `data/cases/<case_id>/video/segments/<revision>/`，校验后原子发布；失败不暴露半成品。原文件不覆盖。准备队列保存在 SQLite 的 `video_segment_jobs` 中，记录计划版本、片段、状态和错误，不依赖浏览器保持打开。

服务以单个 Uvicorn worker 运行，后台串行转码，每次限制 FFmpeg 为 2 个编码线程。正常停止时终止当前转码、移除半成品并恢复排队；异常中断后，下次启动把遗留 processing 恢复为 queued、扫描所有已导入视频并补齐缺失子视频。已完成文件直接复用，失败记录保留，管理员可显式重试。

修改段长或替换源视频会使旧版本排队任务失效，并提前准备新版本全部片段；新计划全部准备好之前不开放标注。已有标注、掩膜、全局帧号和事件 ID 不受准备任务影响。短于一段的视频直接使用已有完整播放文件，无需额外转码。

也可以在运行 Web 服务时用命令排队，命令本身不会另起转码进程：

```bash
ssi-annotator prepare-segments             # 扫描已有病例并排队补齐
ssi-annotator prepare-segments SSI_0001 --retry  # 重试指定病例失败/缺失片段
```

分段计划、标注进度和准备队列自动建表，旧标注数据无需迁移。

8001 已热重载新接口并提供新构建。使用旧后端的正式实例需按现有运维流程更新并重启；本次不打断该实例。

## 验证

合成恒定帧率、变帧率及非零起始 PTS 视频验证分段帧映射；接口覆盖鉴权、版本、Range、完成状态失效、调整限制、失败重试与完整病例导出；新增导入即排队、启动补齐、重启续做、配置更新取消旧计划、复用已有文件和只读接口零转码测试。Chrome 分别验证 OPFS 和 IndexedDB、只请求子视频、全局帧定位、只读上下文、跨段结束与恢复、切段保存及播放暂停。浏览器记录见 [video-segments-20261021.json](benchmarks/video-segments-20261021.json)。这些是功能验证，不对实际 SSH 网络链路承诺固定跳帧时延。

预生成流程的 Chrome 记录见 [video-preparation-20261021.json](benchmarks/video-preparation-20261021.json)：人为阻塞后台生成时确认入口关闭，放行后全部 4 段预生成；两种浏览器存储下遍历所有子任务，转码次数始终为 4，标注入口无 POST 生成请求。
