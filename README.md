# UBE SSI 标注平台

本平台实现《UBE 外科空间智能（SSI）标注执行方案 Protocol v1.0》（`前期材料/标注方案.docx`）。所有病例在同一条视频时间轴上标注。

| 轨道 | 内容 | 形式 | 适用病例 |
| --- | --- | --- | --- |
| 0 | 视频可评价状态 E1/E0 | 连续分段 | 全部 |
| 1 | 空间情境 C1–C6 / CU | 连续分段 | 全部 |
| 2 | 5 个空间锚点可见性 V/N/U/NA | 固定间隔采样（默认 5 s） | 全部 |
| 3 | 空间稳定评分 SCS 2/1/0/U | 与锚点使用同一组采样点 | 全部 |
| 4 | 空间定向丢失 | 事件区间 | 全部 |
| 5 | 空间恢复 | 恢复时间点，系统自动计算 SRT | 全部 |
| 6 | M1–M18 空间里程碑 | 时间点 | 金标准 |
| 7 | 关键结构分割与跟踪 | SAM 3.1 交互分割、传播和专家校正 | 金标准 |

## 开源组件选型

- **SAM 3.1 / SAM 3**（Meta，[facebookresearch/sam3](https://github.com/facebookresearch/sam3)）：用于轨道 7 的交互式分割和视频传播，通过官方 `handle_request` / `handle_stream_request` 接口接入。**SAM 2.1** 作为备选后端，可以在 Apple Silicon 上运行。
- **FastAPI + SQLite**：后端服务。**React + Vite**：前端。**FFmpeg**：视频转码、帧时间戳和抽帧。
- 评估过 CVAT 和 Label Studio。它们适合做框和掩膜，但方案中的核心轨道是“连续分段 + 固定间隔采样点 + 事件/恢复链 + 自动指标 + 固定导出格式”，在通用平台里需要大量变通，医生操作也不顺手。因此轨道 0–6 使用专用界面实现，轨道 7 直接复用 SAM 模型。

## 已实现功能

- **工作台**：以帧为单位定位视频，显示 8 条轨道的可缩放时间轴，标注时以键盘操作为主（按 `?` 查看快捷键）。编辑后自动保存，支持撤销和重做，每次保存都留存完整快照，可以恢复任一历史版本。
- **规则内置**：
  - 不适用锚点按情境固定为 NA，适用锚点只允许 V/N/U；适用关系在“规则设置”中配置，需由 Pilot 确认。
  - E0 区间不进入 SCS 和 LPS 分母。
  - 定向丢失短于预设最短时长（默认 5 s）时报告错误，阻止提交和锁定；允许保存草稿继续修改。
  - 两次事件之间没有出现持续 ≥2 s 的 SCS=2 时报告错误，阻止提交、复核通过和锁定；可保存草稿并一键合并。
  - 恢复点缺失或早于事件结束时报错。
  - 定向丢失事件内出现 SCS=2，或者 SCS=0 但不在任何事件内时给出提示。
  - 里程碑顺序异常时提示；“无法判断”记为 `assessable=0`，不按“未发生”处理。
- **金标准分割**：
  - 按片段建立 SAM 会话，可以设置帧间隔，多个结构可以并行跟踪。
  - 选择片段内的一帧，点击“自动生成当前帧候选”，无需人工提示即可预览多个候选区域；可显示全部、单独查看或隐藏候选。
  - 支持点提示（前景/背景）和框提示，可以向前、向后或双向传播，用多边形补画或擦除做修正。
  - 来源分为 `manual`、`sam_propagated`、`sam_corrected`。只有专家确认后，结构才能计入金标准；未确认的结构会阻止提交和锁定。
- **复核流程**：分配任务（主标注、20% 重复标注、Pilot 独立标注）→ 提交 → 复核通过或退回（必须填写原因）→ 以某一版本为起点建立共识/裁决副本 → 创建者提交 → 另外三位专家确认 → 锁定。锁定后不可修改，并按方案第九节写入病例文件夹。
- **质控**：
  - 单病例和跨病例的标注者间一致性：情境 κ、时间 IoU、边界误差，各锚点 κ，SCS 线性和二次加权 κ，事件 F1、时间 IoU、起止点误差和恢复点误差，里程碑时间差。
  - 采样间隔模拟：用 5 s 数据模拟 10 s 和 15 s 采样，计算 SCS 稳定比例和 LPS 的 ICC(A,1)。
  - 冻结期间不能修改采样间隔和事件阈值；方案修订解除冻结后，已锁定病例仍使用锁定时的规则快照。
- **导出**：`cases.csv`、`context_intervals.csv`、`evaluable_intervals.csv`、`sampled_ssi.csv`、`orientation_loss.csv`、`milestones.csv`、`mask_index.csv`、`annotations_coco.json`（未压缩 RLE）、`review_log.csv`、`metrics.csv`。所有时间同时给出 `time_ms` 和帧号。可以导出每例最终版本，也可以导出全部标注者的版本（供一致性分析）。

## 时间与帧号

导入时，视频会去除音轨和容器元数据，以原帧率、不丢帧的方式转码为可逐帧定位的 H.264，并生成 `video/frame_timestamp_map.csv`。平台的帧号和毫秒时间戳都以该表为准。浏览器定位时取帧显示区间的中点，避免显示成前一帧。这一点已经用逐帧编码的测试视频在 30 fps 和 29.97 fps 下逐帧验证。**画面内烧录的姓名等信息无法自动去除，导入前需要确认视频已经脱敏。**

## 当前帧自动候选（最小版本）

1. 在金标准病例的分割页建立一个片段，等待状态变为“就绪”。
2. 定位到片段内要分割的一帧，点击“自动生成当前帧候选”。按钮会暂停播放，无需先添加结构目标、点提示或框提示。
3. 完成后查看画面上的彩色候选，点击“候选 N”单独查看，也可“显示全部”或“隐藏候选”。切换到另一帧时自动隐藏，点击“返回候选帧”恢复查看。运行中可以取消，失败后可以重试。

该版本在完整画面上自动布置 6×6 个提示点，逐点独立调用现有 SAM 后端，过滤空掩膜、极小/接近全屏的掩膜以及 IoU ≥0.85 的重复结果。网格用于布置提示点，**不会把图像裁成小块**。使用单独的单帧模型会话，并精确读取所选帧，不受片段抽帧间隔影响，也不改变现有提示或已确认标注。

候选只用于当前会话的预览；重新生成会替换上一组，结束片段或服务重启后失效。当前不提供候选采纳、自动解剖分类或候选传播，不写入正式掩膜及导出文件。结果可能遗漏、重叠或包含背景，需要人工判断。`mock` 后端仅产生模拟候选；真实分割请使用下文的 SAM 3.1 启动脚本。

已使用本地真实 UBE 样例和 SAM 3.1 权重验证单帧候选生成及原有提示状态隔离。

需要 Python ≥ 3.11、Node ≥ 20 和 FFmpeg。

```bash

# 启动服务
.venv/bin/ssi-annotator serve --host 0.0.0.0 --port 8000
```

通过 HTTPS 反向代理对外提供服务时，需要设置 `SSI_COOKIE_SECURE=1`。备份对象是整个 `SSI_DATA_DIR`：其中 `ssi.sqlite3` 和 `cases/` 必须一起备份。

### 启用 SAM 3.1（GPU 服务器）

```bash
pip install torch==2.10.0 torchvision --index-url https://download.pytorch.org/whl/cu128
pip install 'git+https://github.com/facebookresearch/sam3.git'
hf auth login                     # 需要先在 huggingface.co/facebook/sam3.1 申请权重
export SSI_SAM_BACKEND=sam3.1     # 可选值：mock（默认，模拟）| sam3 | sam3.1 | sam2
```

无法访问 HuggingFace 时，可以用 ModelScope 下载同一份权重（`pip install modelscope`）：

```bash
python -c "from modelscope import snapshot_download; snapshot_download('facebook/sam3.1', local_dir='/path/to/facebook/sam3.1')"
export SSI_SAM_CHECKPOINT=/path/to/facebook/sam3.1/sam3.1_multiplex.pt
```

补充说明：

- `sam3` 包未声明 `einops`、`pycocotools`、`psutil` 依赖，需要手动 `pip install`。
- 默认关闭 FlashAttention 3（需要 `flash_attn_interface`）；安装后可设置 `SSI_SAM_USE_FA3=1`。
- `sam3_backend.py` 里有两处针对上游 `sam3` 的兼容处理：丢弃 `init_state` 不接受的参数；纯点击交互、没有检测器缓存时保留跟踪得到的掩膜（否则只有提示帧有掩膜）。升级 `sam3` 后需要重新验证。
- 用 `CUDA_VISIBLE_DEVICES` 选择 GPU；SAM 3.1 在单卡上约占 4 GB 显存。

SAM 3 的“框提示”是概念示例框，会检测所有同类实例，不是单目标框。因此 `sam3.x` 后端会把框提示转换为框中心的正点。如果习惯用框初始化，可以改用 `sam2` 后端（需设置 `SSI_SAM_CHECKPOINT` 和 `SSI_SAM2_CONFIG`）。

## 工作版本与最终版本导出

- 病例列表提供独立的“选择工作版本”和“导出已锁定最终版本”入口。
- 工作版本需要明确选择标注任务，可包含尚未提交或未复核的数据。导出文件名包含 `working_<任务ID>`，包内 `export_manifest.json` 记录导出类型、任务 ID、版本号及状态。
- 最终导出仅允许病例已锁定、已指定最终任务，且该任务属于本病例并已复核通过。未锁定、已解锁或未确认的共识版本均不能作为最终版本导出。共识版本需由创建者提交，经过另外三位不同 admin/reviewer 确认后，再返回病例列表锁定；金标准病例必须使用这样的共识版本作为最终版本。
- 项目级最终导出只汇总符合上述条件的病例；`cases.csv` 与各标注表使用相同病例范围，`export_manifest.json` 列出纳入任务和被排除病例。没有合格病例时返回明确错误。全部标注者导出保留工作数据用途，并标记可能包含未复核数据。
- 单病例接口默认为 `mode=final`；工作版本接口为 `/api/cases/<case_id>/export.zip?mode=working&assignment_id=<任务ID>`。仅指定 `assignment_id` 不会绕过最终版本检查，跨病例任务会被拒绝。
- 旧版本若未具备三专家签署记录，不能当作共识最终数据导出。已锁定病例先由管理员解锁，再由共识创建者重新打开、提交并完成三人确认后重新锁定；金标准旧最终版本若为主标注，则先建立共识副本。系统不会伪造历史签署。
- 采样间隔模拟仍可使用未锁定的参考数据，不受最终导出限制影响。


## 锚点适用性与 LPS

不适用锚点固定为 NA，鼠标、快捷键和复制上一采样点均不能修改；适用锚点只允许 V/N/U，空值表示尚未标注。未选择空间情境时不能填写锚点。

修改情境标签、移动或删除情境边界时，会同步更新受影响采样点：变为不适用时写入 NA，变为适用时清除自动 NA、等待重新标注。SCS 和备注保留；跨情境复制不会将上一采样点的 NA 复制到当前适用锚点。撤销、重做及版本恢复遵循同一规则。

后端保存接口拒绝与适用关系冲突的值，并为已有采样点中未填写的不适用锚点补齐 NA；适用锚点留空可保存草稿，但不能通过完整性检查。规则设置必须覆盖 C1–C6/CU，适用列表只能包含合法且不重复的锚点字段。

LPS 只统计 E1 区间中、当前情境下适用锚点的 V/N，按 V/(V+N) 计算；U、NA 和 E0 不进入分母。无有效分母时显示无数据，CSV 留空。工作台指标、导出和采样间隔模拟共用该逻辑。

## 三专家独立共识

共识创建者不计入人数。必须有另外三位不同的管理员（admin）或复核专家（reviewer）对同一轮次、同一内容版本明确同意；普通标注者不能签署，同一专家重复点击不增加人数。需准备至少四个有专家权限的账号（创建者加三位复核者），可由管理员在“项目 → 用户”中创建。

1. 管理员或专家选择已有标注，点击“建立”创建共识副本；完成编辑和必要的掩膜专家确认。
2. 创建者点击“提交三专家共识”。提交前进行完整性检查，仍在建立或传播的分割会话必须先完成；提交后内容进入只读评审状态。
3. 另外三位专家分别打开病例列表中的该共识版本，在“三专家共识”面板填写意见并点击“同意本轮共识”。同意意见可留空（记录为“确认一致”），退回必须填写原因。
4. 三人同意后状态自动变为复核通过；病例列表中共识计数为 3/3，可以选择并锁定。金标准病例不能以仅单人复核通过的原始版本替代三专家共识；普通核心病例仍可使用独立复核通过的原始版本。
5. 评审者可在锁定前撤回自己的确认；人数不足时恢复待确认状态。任何专家退回后，本轮不能继续通过；创建者修改并重新提交，开启新一轮，三人重新确认。
6. 创建者可重新打开已提交或已通过的共识，但全部旧确认随即失效。时序内容、结构目标、掩膜帧或掩膜确认的变化均通过数据库内容版本计数使旧签署失效，覆盖后台 SAM 写入。

工作台显示当前进度、专家意见及完整逐轮签署历史。其他专家操作后可点击“刷新结果”加载最新内容和进度；服务端会拒绝旧页面携带的过期轮次或内容版本，不能在未刷新审阅的情况下沿用旧确认。锁定后禁止退回、撤回和修改。

病例包新增 `qc/consensus_reviews.csv`，项目包新增 `consensus_reviews.csv`，记录轮次、内容版本、专家账号及角色、意见、动作和时间；导出清单附当前共识状态。最终版本导出会重新核验三人确认；读取使用同一数据库快照，避免导出数据与签署状态错位。

数据库启动时自动、幂等地增加 `consensus_state`、`consensus_reviews` 及内容变更触发器，保留已有账号、病例和标注。不把旧版的单人“确认共识版本”当作三人签署。


## 管理员删除用户

管理员在“项目 → 用户”中点击账号右侧“删除”，确认后生效。只有 admin 可调用删除接口 `DELETE /api/users/<uid>`；不能删除当前登录账号，最后一个启用管理员也不能被停用或降级。

- 无任何标注、历史操作或签署关联的账号直接删除；该用户名可重新创建，新账号使用不同编号。
- 有关联记录的账号从用户列表移除，清除密码并禁止登录，已有标注、复核、掩膜修改和三专家签署保留原署名及效力。此类用户名保留，不能用来创建新账号，也不能通过启用或重置密码恢复。
- 删除立即清除该账号全部登录会话；向已删除账号分配新任务会被拒绝。删除账号不会删除其病例或标注数据，未完成任务仍保留。
- 后端保存删除操作的管理员、目标账号名称、处理方式及时间。启动时自动补充 `users.deleted_at` 和 `user_deletion_log`，兼容已有数据库。


## 更新前端后出现 Method Not Allowed

若新页面显示删除等按钮，但接口返回 405（Method Not Allowed），请先在原启动终端按 Ctrl+C，再重新执行 `./scripts/dev-backend.sh`（使用真实 SAM 时执行 `./scripts/dev-sam31.sh`），随后强制刷新浏览器。不要在旧进程仍占用 8001 时重复启动。

开发脚本默认设置 `WATCHFILES_FORCE_POLLING=true`、`WATCHFILES_POLL_DELAY_MS=500`；CLI 热重载仅监控 `backend/ssi_annotator/`，避免依赖挂载目录的文件系统通知，并排除模型、缓存和前端依赖的扫描。脚本本身或环境变量修改仍需重启一次。可通过 `http://服务器IP:8001/openapi.json` 检查实际加载的接口：`/api/users/{uid}` 应同时包含 `patch` 和 `delete`。


## 修改用户角色

管理员在“项目 → 用户”的角色列中选择“标注者 / 复核专家 / 管理员”，再点击“保存角色”并确认。角色选择本身不保存；修改后账号、标注任务及历史记录保留。不能降级最后一个启用的管理员。

后端每次请求均读取当前角色，因此现有登录会话的权限立即更新；被修改用户刷新页面即可同步导航和按钮。修改当前登录管理员自己的角色时页面自动刷新。升级为专家不允许复核自己的原始标注，也不能计入自己创建的共识版本的独立确认人数。

## 锁定病例的规则快照与重复导出

每次锁定病例时，在同一个数据库事务中进行完整性检查、保存完整规则快照并绑定最终标注任务及版本号。快照包含采样间隔、锚点适用关系、事件与恢复阈值等设置，以及方案版本、SHA-256、锁定操作人和时间；快照编号标识本次锁定。后续解除项目规则冻结、修订采样间隔或适用关系，不会改变已有锁定版本的采样表、指标和质控检查。

单病例最终 ZIP、项目级最终主表、病例文件夹重写以及最终任务的工作台均使用该病例的快照。单病例包和病例文件夹新增 `qc/rules.json`，单病例及项目级 `export_manifest.json` 的 `applied_rules` 记录实际规则、来源和快照编号。项目汇总可以包含采用不同规则的病例，不能用一个当前项目间隔解释全部病例；应按清单核对或筛选规则版本。已锁定最终任务即使从“工作版本”或“全部标注者”出口导出，也沿用锁定快照；其他未锁定任务仍使用当前项目规则。

管理员解锁病例后，已提交或通过的任务恢复为进行中，共识旧签署失效，需重新提交复核（共识需重新取得三位专家确认），再按确认的规则重新锁定。旧快照及签署历史保留，新锁定追加新快照，不覆盖旧记录。解锁后的历史 CSV 文件保留在磁盘，只有重新锁定才会写入新版本；在此期间它们不代表当前可交付的最终版本。

服务启动时自动、幂等地增加快照表及病例指针字段。旧版已锁定病例如果没有历史快照，系统无法证明当时的规则，因此不会用当前设置自动回填：最终导出返回明确提示，项目最终汇总排除该病例并说明原因，文件夹重写跳过并保留旧文件。原始标注和历史文件继续保留；工作版本可按当前规则预览/导出，清单明确提示历史规则未知。恢复最终交付前，管理员需确认所用规则，解锁、重新提交复核并锁定。快照校验失败或与最终任务版本不匹配时同样拒绝最终导出。

回归测试位于 `backend/tests/test_rule_snapshots.py`，覆盖 5 秒改为 10 秒后原锁定版本仍保留 6 个采样点、SCS/LPS 与质控结果不变、各出口一致、不同病例规则并存、解锁重审和旧库升级。此保证针对同一实现版本下的规则设置变更；升级指标计算代码或方案定义时仍需独立验证。

## 定向丢失事件必须合并的校验

两次相邻定向丢失之间，如果前一次的恢复时间点到后一次事件起点不足预设稳定时长（默认 2000 ms），系统将其列为必须合并的错误。例如首次恢复点为 7 秒，下一次事件起点为 8 秒，稳定期只有 1 秒，不能记录成两个最终事件；起点为 9 秒时恰好达到 2 秒，可以分开记录。判断依据是人工标记的恢复点，而非前次事件结束时间；固定 5 秒 SCS 采样不用于推断连续 2 秒的稳定性。

草稿可保存，工作台事件面板显示错误及一键合并入口；提交、普通复核通过、共识提交/确认和最终锁定均会阻止未处理的合并错误。合并后需检查保留的首次起点、末次结束/恢复点、主要干扰因素及置信度，再重新提交复核；事件数、OLF 和 SRT 由修改后的记录计算。

单病例最终导出、项目级最终汇总和病例文件夹重写同样检查此规则，防止旧版已通过或锁定的错误数据继续交付。检查使用该病例锁定时的规则快照。存在错误时，单病例最终导出拒绝，项目汇总排除该病例并在清单中说明原因，文件夹重写跳过并保留已有文件；仅工作版本导出继续保留原记录及错误检查，供修正。系统不会自动合并或修改历史标注；旧病例须解锁、合并、复核后重新锁定。
